# v3 — Веб-чат: индикатор ожидания, таймаут и исправление ошибок

**Статус:** утверждён 2026-11-25
**Ветка:** `feature/chat-loading-state` (от `main`, после слияния v2)
**Исполнитель реализации:** автор проекта (вручную)

## Цель

Пользователь веб-чата (`npm start`) всегда видит, что происходит с его вопросом: ответ готовится, пришёл или не получен. Ожидание ответа ограничено по времени. Попутно исправить две найденные ошибки клиента: не показываются источники, в историю диалога записывается не тот вопрос.

## Вне рамок v3

- Учебный пример. Консольный чат — кроме общих для обоих чатов ограничений B1–B2 (решение D4).
- Анимация индикатора, отображение этапов обработки («ищу…», «формирую…»).
- Кнопка отмены запроса пользователем.
- Повторная отправка вопроса после ошибки одной кнопкой.
- Изменения дизайна и вёрстки чата помимо перечисленного.

## Шаги

### Блок A0. Вынос скрипта веб-чата в отдельный файл

- **A0.1.** Перенести скрипт из `public/index.html` в отдельный файл `public/chat.js` без изменения поведения (решение D5).
- **A0.2.** Убедиться, что после переноса чат работает как раньше. Перенос коммитится отдельно, до изменений блоков A–C.

### Блок A. Индикатор ожидания

- **A1.** После отправки вопроса на месте ответа показывать текст «Думаю…».
- **A2.** С приходом первого фрагмента ответа текст «Думаю…» заменяется ответом.
- **A3.** Пока ответ не завершён (успешно или с ошибкой), поле ввода и кнопка отправки неактивны.
- **A4.** После завершения ответа поле ввода снова активно и получает фокус.

### Блок B. Ограничение ожидания и ошибки

- **B1.** Ограничить время ожидания ответа модели (решение D2). Ограничение действует для обоих чатов, веб и консольного (решение D4).
- **B2.** Ограничить количество автоматических повторов запроса к модели при ошибках, включая превышение лимитов (решение D2). Ограничение действует для обоих чатов (решение D4).
- **B3.** Если ответ не получен за отведённое время или повторы исчерпаны, показать в чате понятное сообщение об ошибке вместо ответа.
- **B4.** Если сервер недоступен или вернул ошибку HTTP, показать в чате сообщение об ошибке, а не оставлять ответ пустым.
- **B5.** Причина ошибки (таймаут, лимит, другая) выводится в консоль сервера.
- **B6.** После любой ошибки форма снова доступна (A4).

### Блок C. Исправление ошибок клиента

- **C1.** Источники ответа отображаются под ответом: клиент и сервер используют одно имя события.
- **C2.** В историю диалога записывается текст заданного вопроса, а не строка `'question'`.
- **C3.** Вопрос, завершившийся ошибкой, не записывается в историю диалога.

### Блок D. Проверка (вручную)

- **D1.** Обычный вопрос: виден «Думаю…», затем ответ и источники; форма недоступна во время ответа и доступна после.
- **D2.** Уточняющий вопрос со ссылкой на предыдущий («а сколько дней?»): ответ учитывает историю.
- **D3.** Имитация недоступности модели (например, неверный ключ API): в чате сообщение об ошибке, форма доступна, в консоли сервера причина.
- **D4.** Сервер остановлен: в чате сообщение об ошибке, форма доступна.
- **D5.** Консольный чат (`npm run chat:cli`) отвечает на вопросы как раньше.
- **D6.** `npm run format:check` проходит.

### Блок E. Ревью и слияние

- **E1.** Код-ревью диффа ветки относительно `main`.
- **E2.** Исправить принятые замечания.
- **E3.** Влить ветку в `main`, удалить ветку.
- **E4.** Отметить в этом плане статус «реализовано».

## Журнал решений

| # | Решение | Обоснование |
|---|---|---|
| D1 | Индикатор — текст «Думаю…» на месте ответа + блокировка формы | Выбор автора. Минимум кода; блокировка заодно исключает двойную отправку и перемешивание двух ответов в одном сообщении |
| D2 | Ожидание ответа модели ограничено таймаутом и числом повторов; при превышении — сообщение об ошибке | Выбор автора. Сейчас при ошибке лимита запрос повторяется с растущими паузами, и пользователь ждёт без обратной связи. Конкретные значения — см. «Предложения по мелочам». Подтверждено по документации LangChain JS (Models → Connection resilience): `maxRetries` по умолчанию 6, автоматически повторяются сетевые ошибки, 429 и 5xx с экспоненциальной паузой; 401 и 404 не повторяются; `timeout` задаётся в миллисекундах |
| D3 | Исправления C1–C3 входят в v3 | Выбор автора. Тот же файл и та же логика получения ответа |
| D4 | *Пересмотр 2026-11-25.* Таймаут и лимит повторов (B1–B2) действуют и для консольного чата | Выбор автора. Модель создаётся один раз в `src/rag.ts` и общая для обоих чатов; бесконечное ожидание в консоли так же неудобно. Остальной консольный чат в v3 не меняется |
| D5 | *Пересмотр 2026-11-27.* Скрипт веб-чата выносится в `public/chat.js` отдельным шагом до остальных изменений | Предложение автора. После v3 скрипт вырастет примерно вдвое; в отдельном файле его проще читать. Отдельный коммит переноса оставляет изменения v3 читаемыми в диффе. Сервер не меняется: `public/` уже раздаётся как статика |

## Предложения по мелочам (можно возразить)

- Таймаут ответа модели — 30 секунд, не более 1 повтора.
- Тексты на языке интерфейса чата (украинский): «Думаю…», «Не вдалося отримати відповідь. Спробуйте ще раз.»
